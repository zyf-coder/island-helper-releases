# 灵动助手 · 魅族 22 实况通知增强 App —— 技术方案

> 目标：在魅族 22（Flyme AIOS 2）的屏幕顶部，以"药丸胶囊"形态实时呈现**导航 / 音乐 / 支付**三类信息，并可交互。
> 文档版本：v1.0　｜　目标机型：魅族 22（Flyme AIOS 2，Android 16 底座）

---

## 0. 一句话结论（先看这里）

魅族把灵动岛官方叫 **「实况通知」**，但 Flyme **没有开放任何供第三方 App 往实况通知推送内容的公开 API / Intent**（已逐篇核查魅族开放平台完整文档树，ROM 适配类仅两篇：桌面角标 id=207、系统媒体控件&状态栏歌词 id=239）。

所以本方案**不走"往系统灵动岛里塞内容"**，而走已被市场验证的**自绘路线**：App 自己用悬浮窗在状态栏区域画一个胶囊，自己采集三类数据源。视觉上与系统实况通知一致（同一位置、同样交互），但不依赖系统白名单，因此**任何机型都能用**，且不受魅族逐 App 开关限制。

这正好落在用户的三个决策上：三者整合到同一界面、允许旁路手段并引导授权、先出方案。

**分层职责**

- **采集层**：三个独立 Source，只负责产出统一格式的 `IslandCard` 数据，不关心 UI。
- **状态总线**：`IslandState` 单例持有当前活跃卡片，按优先级选择展示哪一张。
- **渲染层**：只认 `IslandState`，状态变化才重绘，避免高频数据导致抖动。
- **辅线**：角标与 Live Updates 是"锦上添花"，失败不影响主功能。

## 3. 灵动岛界面设计

统一一个胶囊，三种卡片形态。设计锚点：Flyme 实况通知的药丸造型（圆角胶囊 + 深色/浅色自适应）。

```
  ┌── 收起态（药丸，高 36dp，居中顶部）──────────────────┐
  │  ⦿ 音乐   ♪ 平凡之路 - 朴树      ⏸  ⏭   │        │
  └────────────────────────────────────────────────────┘
        ↓ 点击展开
  ┌── 展开态（面板，宽度 92% 屏宽）────────────────────┐
  │  封面 128x128   平凡之路                         │
  │                朴树 · 专辑名                     │
  │                ♀ 02:14  ──○──── 03:57           │
  │  [⏮]  [⏯]  [⏭]      [≡ 歌词]  [✕ 收起]        │
  └────────────────────────────────────────────────────┘
```

**三种卡片形态**

| 场景 | 收起态内容 | 展开态内容 | 优先级 |
|---|---|---|---|
| 导航 | `↱ 右转 300米` + 剩余 12 分钟 | 转向箭头、下一路名、剩余距离/时间、结束按钮 | **最高**（时效性强，驾驶中不可错过） |
| 音乐 | 封面缩略 + 歌名 + ⏯ ⏭ | 封面、歌手、进度条、上一首/播放/下一首、歌词入口 | 中（可后台共存，但导航优先） |
| 支付 | `✓ 收款 ¥88.00` | 金额、付款方备注、时间、订单号 | 短暂高优先（3 秒后自动降级/淡出） |

**优先级仲裁规则**

1. 同一时刻只显示一张卡，导航 > 支付(播报中) > 音乐。
2. 支付播报 3 秒后淡出，恢复上一张。
3. 音乐卡常驻直到播放停止或用户收起。
4. 导航开始时音乐卡缩为"极简态"（仅保留 ⏯/⏭ 两个小按钮）挤在胶囊尾部，不完全消失。

## 4. 三条数据链路（逐场景设计）

### 4.1 音乐：任意播放器

**数据源**：`MediaSessionManager.getActiveSessions()` 反向读取当前活跃媒体会话（需"通知使用权"权限）。

```
MediaSessionManager.getActiveSessions()
  → 取最近 active 的 session
  → MediaMetadata: TITLE / ARTIST / ALBUM / ART_URI
  → PlaybackState: STATE_PLAYING / BUFFERING / POSITION
  → 封面: ART_URI → HttpURLConnection 取图（带缓存 LRU）
```

**控制**：我们不接管播放（不能替别的 App 播），但可以通过 `MediaController`（拿到 `Token` 后 `MediaController.newBuilder(token).build()`）转发 `setPlayState`/`skipToNext`/`skipToPrevious`。注意：**MediaButton/KeyEvent 已废弃**，必须走 `MediaSession.Callback`。

**为什么这样能覆盖"任何音乐软件"**：网易云、QQ 音乐、酷狗、Spotify、YouTube Music 等全部遵循 MediaSession 协议，系统级的"音乐 App 列表"就是这么来的。这是 AOSP 标准，不是 Flyme 私有，是唯一真正通用的路径。

**备选/补充**：Flyme 的"系统媒体控件 & 状态栏歌词"是官方开放能力（id=239）——基于 `Notification.tickerText` + 反射 `FLAG_ALWAYS_SHOW_TICKER` / `FLAG_ONLY_UPDATE_TICKER`。这可作为**状态栏歌词**辅线，不做胶囊。

**风险**：部分 App 不规范（不发布 MediaSession 或元数据不全），需在 UI 上做"未知来源"降级。

### 4.2 导航：高德 / 百度

**没有免费通用接口**——第三方无法反向读取高德/百度 App 内部的导航会话。三级降级：

| 级别 | 方案 | 说明 | 可靠性 |
|---|---|---|---|
| L1 优选 | **自建导航**：集成高德导航 SDK (`AMapNavi`)，由我们的 App 发起导航 | `NaviInfoCallback` 拿到转向、剩余距离/时间、限速。数据完整、可控 | 高 |
| L2 | 高德/百度 URI 调起 + 通知文本解析 | 用 `amapuri://route/plan` 调起导航，再从通知栏读其"剩余3公里右转"类文本 | 中，文本格式会变 |
| L3 | 引导用户到 Flyme 系统设置的「实况通知」里给高德/百度开权限 | 用系统的百度地图实况通知（Flyme 12.4.0.0A 已支持），我们只做引导 | 依赖系统 |

**MVP 取 L1+L3**：主推"从灵动助手发起导航"（我们自己拿数据画胶囊，体验最好），同时做引导页告诉用户"系统设置 → 通知和状态栏 → 实况通知"里可以给高德/百度开原生实况通知（因为用户只要接受官方卡片，这本身也是灵境岛体验）。

> 若用户不接受"从我们 App 发起导航"，只能退到 L2（通知文本解析），准确率与稳定性都会打折。

### 4.3 支付：支付宝 / 微信

**三选一，按合规性排序**：

| 方案 | 做法 | 合规风险 | 建议 |
|---|---|---|---|
| P1 优选 | **自有服务端**：我们自己有收款商户后端，微信/支付宝异步回调 → 服务端推我们的 App（或 App 拉单） | 无 | **强烈推荐**。真相永远来自服务端 |
| P2 | 通知监听 `NotificationListenerService` 读支付宝/微信收款通知 | 高：资金信息读取、诱导监听，Flyme 有《APP 隐私合规检测标准》 | 仅个人自用，不上架；或用户主动开启后明确告知用途 |
| P3 | 无障碍服务读屏 | 极高 | 不做 |

**关键设计原则**：App 只做**展示**，支付真相（金额、订单号）永远来自服务端或用户手动确认，**不从通知文本里解析金额用于记账**。

## 5. 权限清单与引导流程

| 权限 | 用途 | 是否必需 | 获取方式 |
|---|---|---|---|
| `SYSTEM_ALERT_WINDOW` | 画胶囊悬浮窗 | 必需 | 设置跳转 |
| `BIND_NOTIFICATION_LISTENER_SERVICE` | 读 MediaSession（音乐）、导航文本、支付通知 | 必需（音乐场景） | 设置跳转 |
| `POST_NOTIFICATIONS` | 辅助通知通道 | Android 13+ 必需 | 弹窗 |
| `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` | 后台保活 | 强烈建议 | 设置跳转 |
| 无障碍服务 | 仅 P3 备用 | 可选 | — |
| `FOREGROUND_SERVICE` (+ mediaPlayback 类型) | 前台服务保活 | 必需 | 代码申请 |

**引导页设计**（App 首次启动）：4 步卡片式引导，每步一个明确按钮 + 一句人话说明，直达对应系统设置页。

```
① 允许悬浮窗  → "灵动助手需要悬浮窗权限，才能在屏幕顶部显示胶囊"
② 允许通知使用权 → "用于读取你正在播放的音乐和导航信息"
③ 关闭电池优化 → "避免系统在后台杀掉灵动助手"
④ 选择音乐应用白名单（可选）→ 提升 MediaSession 读取准确率
```

同时提供一个 **"一键跳系统设置"** 的总入口。

## 8. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 部分音乐 App 不发布完整 MediaSession | 信息缺失 | 降级为"仅播放/暂停"，UI 显示未知来源 |
| 悬浮窗在部分 ROM 被限制 | 胶囊不显示 | 引导电池优化白名单；失败则降级为常驻通知 |
| 后台被杀 | 服务中断 | 前台服务 + 电池优化白名单 + 通知监听唤醒 |
| 支付通知监听触碰合规 | 上架被拒 | 默认关闭 P2，走 P1；隐私政策明示；不上架仅自用 |
| 导航文本解析格式变更 | L2 失效 | L1 为主，L2 仅作辅助，随时可切 |
| 厂商 ROM 差异（Flyme vs 其他） | 行为不一致 | 悬浮窗方案本身与 ROM 无关，天然通用 |

## 9. 尚待你确认的三个决策点

1. **导航是否接受"从灵动助手发起"**（L1）？若不接受，只能用通知文本解析（L2），准确率会打折。
2. **支付是否有自己的收款后端**？有 → 走 P1（推荐）；没有 → 只能 P2 通知监听（仅自用，不上架）。
3. **是否要上架应用商店**？决定合规投入量级；纯自用可以砍掉很多合规工作。
